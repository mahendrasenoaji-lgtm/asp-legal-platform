## 2. Functional testing

- Navigation: every header, drawer, footer and breadcrumb link resolves, in both locales.
- Language switcher lands on the equivalent page, not the homepage. This is the single most
  common bilingual bug.
- Intake form: required-field validation, file type and size rejection, oversized upload,
  malicious file (EICAR test string), double submit, rate limit trip.
- Search: no results, one result, many results, non-Latin input, `'` and `%` injection.
- Filters: chips on Insights and Cases, including the empty-result state.
- CMS: create, edit, schedule, publish, archive; confirm an author without publish rights
  cannot publish; confirm the four database guards reject bad rows.
- Empty states render when a collection is genuinely empty, not only when it is missing.

## 3. Accessibility — target WCAG 2.2 AA

- Automated: axe-core on every template. Zero criticals before launch.
- Keyboard-only pass through the intake form and the mobile drawer, including focus return.
- Screen reader pass (NVDA and VoiceOver) on homepage, practice, profile, intake.
- Zoom to 200% and 400% without loss of content or function.
- `prefers-reduced-motion` honoured — verify the hero sequence and scroll reveals stop.
- Confirm no `user-scalable=0` survives the migration.

## 4. Performance

Lighthouse on homepage, practice, lawyer, article, contact. Targets: Performance > 90,
Accessibility > 95, Best Practices > 95, SEO > 95; LCP < 2.5s, INP < 200ms, CLS < 0.1.

Watch items specific to this build: the display face at hero size is the LCP element, so
self-host with `font-display: swap` and preload one weight; reserve aspect-ratio boxes for
portraits so CLS stays flat when photography finally arrives; serve WebP/AVIF.

## 5. Responsive

Test at 320, 375, 390, 768, 1024, 1440 on iOS Safari, Android Chrome, desktop Chrome,
Firefox and Safari. Specific risks: the proceeding register (horizontal scroll must not trap
the page scroll), the case table's card fallback below 700px, and the drawer at 320px.

## 6. Content QA

- No `lorem`, `hello world`, `be my guest`, `nulla magna`, `TODO` or `DEMO` string anywhere
  in production output. Grep the build, do not trust review.
- Every published article has an author who exists, a publication date and a reviewer.
- Every award links to the awarding organisation's own page.
- No matter published without `is_public`, a source URL and a named clearance.
- The 40-vs-23 headcount discrepancy is resolved, or the number is removed.

## 7. Security review

Header verification against the live origin, `npm audit` clean, secrets absent from the
repository history, auth and RBAC probed with a low-privilege account, upload controls tested
with the EICAR file and with a renamed executable.

## 8. Sign-off gate

Launch is blocked until: zero critical accessibility issues, all Lighthouse targets met,
the redirect map validated against a full crawl plus Search Console, the security review
closed, and the content QA grep clean.
