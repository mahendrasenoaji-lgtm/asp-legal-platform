Summary

The current site works — and that is the problem.

asplawyer.co.id loads, has a phone number, and lists the firm’s practice areas. It also runs unpatched WordPress plugins with known exploit histories, exposes its admin login and REST API to anyone who requests them, and has carried a default “Hello world!” post and demo Fashion/Music categories live on its News page since setup. None of that is visible to a client calling the firm — all of it is visible to anyone who looks, including opposing counsel doing diligence before a referral.

The rebuild replaces the platform, not just the look: a Next.js application backed by a PostgreSQL schema whose constraints refuse to let a practice page, an article, or a case publish without the person or source behind it — the “never invent content” rule enforced in the database, not just in a style guide. What follows is a direct comparison, not a sales pitch: screenshots side by side, and audit numbers from the same tool (Lighthouse) run against both sites the same way.

Security

What was actually found, testing both.

Legacy

Admin surface is publicly reachable

/wp-admin/, /wp-login.php, /xmlrpc.php and /wp-json/ all resolve today with no restriction. xmlrpc.php and exposed REST endpoints are among the most common WordPress attack vectors in active use.

Legacy

No Content-Security-Policy header

HSTS and a couple of other headers are present via the host, but nothing restricts which scripts or styles the page will execute if one gets injected.

Rebuild

Headers verified against a real browser, not just curl

The first CSP attempt looked correct in curl and even rendered visually — but a real headless-Chrome audit caught it silently blocking every script on the page, breaking the mobile menu and form validation entirely. Fixed with a hash-based policy computed from the actual build output and shipped report-only during rollout, the standard way to introduce a new CSP without risking an unverified edge case taking the site down.

Rebuild

Bad data is rejected at the database, not just the form

Four constraints in the schema were tested directly: a practice page cannot publish without a named lead lawyer, an article cannot publish without a real author, a matter cannot publish without a public source and named clearance, and an award cannot exist without the awarding body’s own listing. All four were confirmed to reject the bad row, not merely documented as a rule.
